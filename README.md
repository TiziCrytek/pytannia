# Питання 🌷

Маленький сайт із трьома питаннями: «розкажеш, чому така сумна?», «як тобі
зручніше розповісти?», «що мені зробити, щоб трохи підняти тобі настрій?».
Кнопки «ні» та «не хочу» не працюють, а відповіді одразу приходять тобі
в Telegram (або на пошту). Усе статичне — ні сервера, ні бази даних.

## Як подивитися локально

Просто відкрий `index.html` подвійним кліком — усе працює і без сервера.
Якщо хочеться «як на хостингу»:

```bash
python -m http.server 8000
```

і відкрий http://localhost:8000

## Що змінювати

Усе наповнення — в одному файлі **`js/config.js`**:

| Що | Де |
| --- | --- |
| Ім'я подруги | `friend` |
| Перший екран | `intro` |
| Питання | `questions` |
| Фінальний екран | `final` |
| Куди надсилати відповіді | `delivery` |

`index.html`, `css/style.css` та `js/app.js` чіпати не потрібно. Кольори
та шрифти — на початку `css/style.css` (блок `:root`).

### Типи питань

```js
{ id: 'why', type: 'yesno', text: 'Розкажеш, чому така сумна?', yes: 'Розкажу', no: 'Ні' }

{ id: 'how', type: 'choice', text: 'Як?', options: [
    { label: 'Розкажу в телеграмі', emoji: '💬' },
    { label: 'Розкажу, якщо попросиш', emoji: '🤲' },
] }

{ id: 'take', type: 'multi', text: 'Що взяти?', options: [ ... ] }

{ id: 'time', type: 'time', text: 'О котрій?', presets: ['18:00', '20:00'] }

{ id: 'wish', type: 'text', text: 'Чим порадувати?', placeholder: '...' }
```

У питання може бути `hint` (підпис під питанням) і `short` (коротка назва
в підсумку). У `yesno` — `noLabels` (тексти кнопки «ні» по спробах),
`noLimit` (після скількох спроб вона здається) і `surrender` (що на ній
буде написано в результаті).

### Варіанти, які «не працюють»

```js
{
  label: 'Не хочу розповідати',
  locked: true,                                  // не вибирається
  tease: ['Не хочу розповідати', 'Ну хоч трохи?'], // тексти по натисканнях
  unlockAfter: 4,                                 // після 4 спроб
  unlockLabel: 'Гаразд, розкажу в телеграмі',     // стає робочою
}
```

```js
{ label: 'Розкажу завтра', locked: true, swapTo: 'Давай краще сьогодні' }
```

Тут варіант одразу після першого натискання змінює текст і стає робочим.

### Свій варіант

```js
{
  label: 'Свій варіант',
  custom: true,
  customLabel: 'Напиши, як тобі було б приємніше',
  customPlaceholder: 'наприклад: просто помовчати разом…',
}
```

Відкриває поле, куди вона вписує свій текст.

## Куди приходять відповіді

Відповіді надсилаються автоматично, щойно вона відповість на останнє
питання. Нічого пересилати не треба.

### Варіант 1 — Telegram (рекомендую)

Найшвидше: повідомлення приходить пушем.

1. У Telegram знайди **@BotFather** → `/newbot` → придумай ім'я. Він видасть
   токен виду `123456789:AAE...`.
2. Відкрий свого бота (посилання BotFather дасть) і натисни **Start** —
   без цього бот не зможе тобі писати.
3. Знайди **@userinfobot**, натисни Start — він надішле твій числовий `id`.
4. Впиши обидва значення в `js/config.js`:

   ```js
   delivery: {
     method: 'telegram',
     telegram: {
       token: '123456789:AAE...',
       chatId: '123456789',
     },
   },
   ```

**Про безпеку:** токен лежить у коді сторінки, тобто його видно всім, хто
відкриє сайт. Для особистого бота це некритично, але якщо хочеш — у
@BotFather є `/revoke`, який випускає новий токен (старий одразу перестає
працювати). Або використай Web3Forms нижче.

### Варіант 2 — пошта через Web3Forms

Лист приходить на звичайну пошту, нічого ставити не треба.

1. Зайди на [web3forms.com](https://web3forms.com), введи свою пошту й
   натисни **Create Access Key**. Ключ прийде на цю ж пошту (і покажеться
   на сторінці) — він виглядає як UUID: `a1b2c3d4-...-1234567890ab`.
2. Підтверди пошту за посиланням у листі від Web3Forms — без цього
   надсилання не працює.
3. Впиши в конфіг:

   ```js
   delivery: {
     method: 'web3forms',
     subject: 'Відповіді',
     web3forms: {
       accessKey: 'a1b2c3d4-...-1234567890ab',
       fromName: 'Відповіді',
     },
   },
   ```

4. Запуш зміни й перевір: пройди всі питання на сайті — лист має прийти
   протягом кількох секунд. Перший лист іноді потрапляє у «Спам».

Ключ публічний за задумкою сервісу, але він прив'язаний до твоєї пошти:
стороння людина з ключем теоретично може надіслати тобі лист через форму.
На безкоштовному тарифі є ліміт надсилань (250 на місяць).

Якщо лист не приходить — відкрий сайт, натисни F12 → Console: там буде
видно відповідь Web3Forms (найчастіше — непідтверджена пошта або ключ
скопійований не повністю).

### Вимкнути надсилання

```js
delivery: { method: 'none' }
```

Відповіді будуть лише на екрані (можна скопіювати кнопкою).

## Публікація на GitHub Pages

1. Створи на GitHub новий **публічний** репозиторій, наприклад `pytannia`.
   На безкоштовному тарифі Pages працює лише з публічними репозиторіями.
   *(Приватний репозиторій + Pages потребує GitHub Pro.)*
2. Завантаж файли з цієї папки в корінь репозиторію — `index.html` має
   лежати саме в корені. Можна перетягнути через веб-інтерфейс GitHub або
   через git:

   ```bash
   git init
   git add .
   git commit -m "invite"
   git branch -M main
   git remote add origin https://github.com/ТВІЙ_НІК/pytannia.git
   git push -u origin main
   ```

3. У репозиторії: **Settings → Pages → Build and deployment**
   → Source: **Deploy from a branch**
   → Branch: **main**, тека **/ (root)** → **Save**.
4. Через хвилину сайт буде за адресою:

   ```
   https://ТВІЙ_НІК.github.io/pytannia/
   ```

Якщо пізніше зміниш питання — запуш зміни, Pages оновиться сам.

> Важливо: вміст сторінки бачать усі, хто має посилання на сайт, а адресу
> `https://ТВІЙ_НІК.github.io/pytannia/` легко вгадати. Не пиши туди нічого,
> що не має бути публічним.
